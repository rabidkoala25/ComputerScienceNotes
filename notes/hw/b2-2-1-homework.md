## *3.*
| Feature | Static Data Structure | Dynamic Data Structure |
|----------|----------|----------|
| Size | Fixed. Set when the structure is created | Flexible. Can grow or shrink as needed |
| When memory is allocated | At compile time | At runtime |
| Can it resize during runtime? | No | Yes |
| Example | Array | Linked list, Python list |
| Advantage | Fast and direct access by index | easy to insert and delete items |
| Disadvantage | Can waste memory if not full, or overflow if too small | Slower access  |

## *4.*

a) Static. Always 12 months, never changes.

b) Dynamic. No idea how many items someone will add, and they can remove them too. Size keeps changing.

c) Dynamic. New posts all the time, no limit.

d) Static. 7 days, always.

e) Dynamic. Jobs constantly added and finished, so the queue grows and shrinks.

f) Static. Exactly 10 scores. New high score just replaces the lowest one, so size stays the same.

## **5.**

Dynamic isn't always better. Depends on the problem.

Reasons it may be less suitable:

- Extra memory needed. 
- Slower access. 
- Allocation at runtime takes longer. 
- More complex to program.
